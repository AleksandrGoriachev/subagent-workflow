# Правило размера файлов

Рукописный производственный файл кода **больше 600 строк** — повод пересмотреть
его структуру при следующей правке; **больше 900 строк** — отдельная задача
(контракт, красный, приёмка), а не «поправлю по ходу».

Правило проверяется машиной, а не памятью: `node spec/checks/code-size.mjs c1`
падает при превышении 900 и печатает WARN-список файлов больше 600.

## Область

- `plugin/lib/**`, `plugin/client/**` — панель.
- `spec/scripts/**`, `spec/checks/**` — движок и его проверки.
- `tools/**` — инструменты пакета.

## Исключения

1. `plugin/lib/client.js` — сгенерированный артефакт: склейка
   `plugin/client/*.js` (сборка `plugin/tools/build-client.mjs`). Загрузчик DSH
   отдаёт один классический скрипт; размер артефакта не считается размером
   исходника. Порог применяется к фрагментам.
2. `plugin/test/**` — тесты: отдельный контур, его навигация чинится отдельно
   (кандидат — разбиение `api.test.mjs` по группам маршрутов).

## Как применять

1. Пересёк 600 строк — при следующей правке вынеси связную часть в модуль.
2. Пересёк 900 — останови правку и оформи задачу на раскладку.
3. Правка без задачи допустима только пока файл ниже 900; исключение — правка,
   которая сама уменьшает файл.

Проверка: `node spec/checks/code-size.mjs c1` (входит в ворота задач, которые
меняют код панели или движка).
