# Стабильная адресация папок обмена: uid вместо генерируемого имени

Дата: 2026-11-12. Заказчик: «папки не имеют идентификаторов как таковых — их названия генерируются
программно по шаблону; должен быть uuid, не отображаемый на графе, но использующийся для адресации».

## 1. Что есть сейчас

`structure/graph.json`:

```json
"folders": [
  {
    "id": "folder-1",
    "brief": "обмен с workflow",
    "box": { "path": "C:/.../coordination/threads/exchange", "root": "C:/.../dsh-project-graph" },
    "participants": ["structure", "workflow"],
    "exchange": { "threads": ["exchange"] }
  }
]
```

Проблемы:

1. `id` — отображаемое имя, генерируемое по шаблону (`folder-1`), меняется при переносе/пересборке;
2. адресация письма идёт по **пути ящика** и по **подписи участника** (`To: structure`), а не по
   идентификатору папки;
3. переименование папки или шаблона ломает историю и резолв адресата (что мы и наблюдали).

## 2. Целевая модель

```json
"folders": [
  {
    "uid": "6f1c2c1e-6d3a-4c55-9a51-2f0f5c1b7e42",
    "id": "folder-1",
    "name": "обмен со workflow",
    "box": { "path": "...", "root": "..." },
    "participants": ["structure", "workflow"],
    "exchange": { "threads": ["exchange"] }
  }
]
```

- **`uid`** — UUID v4, генерируется один раз при создании папки, **не отображается** на графе
  (панель показывает `name`/`id`);
- **`id`** остаётся человекочитаемым ключом для панели и совместимости;
- адресация — по `uid`.

### Формат письма

```text
Format: dsh-exchange/1
From: workflow
To: structure
Box: 6f1c2c1e-6d3a-4c55-9a51-2f0f5c1b7e42   ← новое, стабильная адресация
Date: ...
```

Правила:
1. Письмо с `Box: <uid>` адресуется папке с этим uid (путь вычисляется из `folders[].box`);
2. Письмо без `Box` — старый путь (по каталогу, где лежит файл) — обратная совместимость;
3. Если uid не найден в графе — отказ `unknown-box` с указанием uid, а не догадка по пути.

## 3. Точки изменений (код)

| Файл | Изменение |
| --- | --- |
| `lib/graph.js` | парсинг `folders[].uid`: валидный UUID v4, при отсутствии — генерация один раз и запись в граф; дубликаты uid — ошибка |
| `lib/boxes.js` | индекс `uid → box`; `resolveFolderBox` принимает uid |
| `lib/exchange.js` | `writeExchangeMessage` пишет `Box: <uid>` при наличии |
| `lib/exchange-watch.js` | `parseMessage` читает `box`; резолв адресата: сначала uid, затем текущий путь; причина отказа — в журнал |
| `lib/api.js` | панель: `uid` не показывать, `name` показывать; при создании папки генерировать uid |
| `checks/0223-*.mjs` | критерии стабильной адресации |
| `test/exchange-uid.test.mjs` | поведенческий тест: переименование папки не меняет адресацию |

## 4. Миграция

1. Скрипт `tools/folders-uid.mjs`: для каждой папки без uid генерирует UUID v4, пишет обратно в
   `structure/graph.json` (одним коммитом), печатает таблицу `id → uid`;
2. Письма начинают писаться с `Box:` с момента включения, старые не переписываются;
3. Панель не показывает uid; при экспорте графа uid сохраняется (иначе пересборка его потеряет —
   см. 0213, `buildGraphDocument` должен копировать `uid` как объявление).

## 5. Критерии приёмки (0223)

- C1: `graph.js` валидирует/генерирует uid; дубликаты — ошибка;
- C2: `buildGraphDocument` сохраняет uid (иначе пересборка теряет адресацию);
- C3: `exchange.js` пишет `Box:`;
- C4: `exchange-watch` резолвит папку по uid и, при отсутствии, пишет `unknown-box`;
- C5: тест: переименование `id` папки не меняет доставку (uid стабилен);
- C6: миграция существует и идемпотентна (повторный запуск не меняет uid).

## 6. Почему это важно для сегодняшнего дефекта

Сейчас письмо привязано к **пути ящика** и к **подписи**, которую вычисляет резолвер. Переименование
папки/шаблона или смена `id` меняет корень и ломает вручение — при этом в журнале это видно только
как `skip:cooldown` (до 0221/0222). uid делает адресацию инвариантом данных, а не выводом из путей.
