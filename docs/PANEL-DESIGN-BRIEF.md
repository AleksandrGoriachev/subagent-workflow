# Бриф: панель workflow-консоли — читаемость и эргономика

Заказчик: «дизайн ужасный». Задача — привести панель плагина `dsh-workflow-console` в читаемое и эргономично организованное состояние. Название карточки «Семантические якоря» СОХРАНИТЬ (решение заказчика).

## Где код
- `subagent-workflow-v2/plugin/lib/client.js` — вся панель (React через `h(...)`, стили в объекте `S`, ~3500 строк).
- `subagent-workflow-v2/plugin/lib/api.js` — маршруты (`/api/status`, `/api/anchors`, `/api/anchors/approve`, `/api/release-check`).
- `subagent-workflow-v2/plugin/README.md` — правило: элемент без объяснения не выходит.
- Тесты: `subagent-workflow-v2/plugin/test/*.test.mjs` (полный набор 210+, все должны проходить).

## Что сейчас есть в панели (инвентарь)
1. Шапка: название, версия движка/панели, кнопка «Проверить актуальность», строка последнего релиза.
2. Карточки: «Версия движка» + действия (обновить движок/панель), «Семантические якоря», доска задач, карточка задачи, политика.
3. Состояния: загрузка, ошибка, «движка нет», внешний движок (409 engine-external).

## Проблемы, которые надо снять
- Визуально: всё одним потоком карточек без иерархии; кнопки вперемешку с текстом; нет отступов/акцентов; тёмная тема не выдержана.
- Эргономика: действия (обновить, проверить, утвердить) разбросаны; непонятно, что главное на экране; нет состояний «идёт операция» рядом с действием.
- Читаемость длинных текстов: подсказки — простыни; список из 12 правил спрятан в свёрнутый блок.
- Нет единого места, где видно «что сейчас не так» (движок, версия, якоря, задачи в работе).

## Требования (обязательные)
1. **Список якорей читается без раскопок**: видимый блок со списком (или явная кнопка «показать список» рядом), с формулировкой и статусом каждого правила; длинный список — со своей прокруткой, а не растягиванием страницы.
2. **Каждый элемент объясняет себя** (правило из README): что это, что будет при нажатии, что сломается без нажатия. Термины — с расшифровкой.
3. Ничего не удалять из функций: обновление движка/панели, проверка актуальности, якоря, доска, карточка задачи, политика.
4. **Read-only по исходникам воркспейсов.** Панель не правит код и задачи проекта: никаких записей в `lib/`, `structure/`, `docs/tasks/` чужих корней. Операции контура — её работа и read-only не нарушают: обновление движка, обновление пакета панели, guard, deploy, привязка движка, создание задания, task-hash/замок, подпись семантических якорей. (Уточнение заказчика 10.11: прежняя формулировка «только подпись якорей» была слишком буквальной и противоречила назначению панели.)
5. Только существующие зависимости; никаких новых пакетов, шрифтов и картинок извне.
6. Русский язык интерфейса; тексты согласует заказчик ДО релиза (сначала макет/скрин текста, потом код).
7. Тесты: `node --test test/*.test.mjs` (списком файлов) — зелёные; `node tools/check-version.mjs` — OK.

## Что нужно на выходе (в этом порядке)
1. **Макет**: схема экрана (блоки сверху вниз), состояния (пусто/загрузка/ошибка/идёт операция), список действий с местами. Текстом, без кода — на утверждение заказчику.
2. **Реализация**: правки `client.js` (+ `S`-стили), при необходимости — аккуратные правки `api.js` (только если нужны новые данные).
3. **Проверка**: тесты, `node --check` на изменённых файлах, ручной прогон панели (если доступен), краткое описание что изменилось.

## Границы
- Не менять движок (`spec/`), не трогать чужие воркспейсы, не выпускать релиз — релиз делает workflow после приёмки заказчиком.
- Не переписывать тексты якорей: это содержание (`docs/anchors.json`), согласовано отдельно.
