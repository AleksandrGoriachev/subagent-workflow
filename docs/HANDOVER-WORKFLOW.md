## 4. Рабочие приёмы (чтобы не наступать заново)

- Двухфазный релиз: подготовка без коммита (git add -A; git write-tree; git archive <tree>; pack-plugin;
  pack; sha256) -> preflight OK -> task-verify -> task-accept узлом judge (--node judge --deviation) ->
  commit.ps1 -Tag -Push -> архив из тега + sha256 -> публикация узлом release-1.
- Критерии задачи выпуска НЕ должны требовать тег текущей версии или «релиз опубликован» (они появляются
  после приёмки) — иначе task-verify откажет (HEAD == contractCommit).
- Артефакты задания (criteria.lock, red.json, gates.jsonl) не коммитить до приёмки; чужие артефакты
  уносить из дерева в .tmp.
- task-accept требует ключ по окну ротации (0081) — чистка acceptors.json больше не нужна.
- Проверки, запускающие pwsh, не должны сверять кириллицу (0083) — только коды выхода.

## 6. Правила (кратко)

- Релиз — узлом release-1; приёмка — узлом judge; человек — только там, где риск требует подписи.
- Данные/настройки узлу релиза передаёт координатор в задании, не профиль/плагин.
- Коммит пакета — только tools/commit.ps1; в воркспейсе тоже tools/commit.ps1 (создан).
- Чужие воркспейсы не читать/не запускать без указания; переписка — через coordination.
- Утверждения о системе — со ссылкой на файл/строку/вывод; нет источника — «не подтверждено».
