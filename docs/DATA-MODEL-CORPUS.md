# Закреплённый корпус для миграции на исполнителя ограничений (P0–P1)

Дата: 2026-11-10. Основание: спецификация DATA-MODEL-SPEC-v0.2, §6.

Корпус замораживается ДО старта P0: вердикты текущих проверок и нового исполнителя
сравниваются на этих пяти задачах по хешам ниже. Изменение артефакта задачи после
заморозки — повод пересобрать корпус, а не подогнать хеш.

| --- | --- | --- | --- | --- |
| 0004 | ранняя, без цепочки | 740e1e7252f8d85a | 3a4b54d7b7c127a6 | нет (генезис-путь) |
| 0030 | средняя, без цепочки | 02e1f9a173ea5ce4 | eb2a83818b37adef | нет (генезис-путь) |
| 0061 | средняя, с цепочкой | 7d69f18c3cb0816c | fe48d7abb06e928b | 3c0c06c87a81bb33 |
| 0074 | якорная эпоха | 7dc4c28c65890185 | 6037a8d59893820d | b1bc294d5fe00824 |
| 0076 | последняя | e96879b967673851 | b0b8ff7a032fd3f8 | b1dc5927e6318c5a |

Полные хеши — в файле `docs/DATA-MODEL-CORPUS-hashes.json` (записан вместе с этим документом).

Почему именно эти пять:
1. покрыты обе ветки C7 — записи без генезиса (0004, 0030) и с цепочкой (0061, 0074, 0076);
2. покрыты три эпохи процесса: ранняя приёмка, критерии+журнал, якорная;
3. у всех есть acceptance.json и verify.json — с чем сравнивать вердикт исполнителя.
