Ревью: адвокат дьявола (worker-2, gpt-6-luna) — «не готово»; эксплуатант (worker-3, glm-5.3-flash) — «готово с условиями».

## 1. Принципы

1. **Факт неизменяем.** Исправление — новый факт со ссылкой на старый (`supersedes`).
2. **Ограничение — предикат над фактами.** Не вызывает проверки и не решает «как искать».
3. **Мнение — тоже факт**, но с провенансом: `judgment` привязан к хешу артефакта и не считается доказательством.
4. **View не хранится как истина.** Панель, статусы, свежесть — вычисляются.
5. **Структурная связность, а не истинность.** Схема не даёт построить запись без обязательных связей; правдивость
   наблюдения обеспечивает доверенный источник (§2), а не хеш-цепочка. Мусорный факт допустим, но не должен
   улучшать вердикт (монотонность, §5).
6. **Проверка проверяющего не нужна.** Свойство «ограничение краснеет» генерируется (§5).

## 2. Отношения (append-only, одна цепь, один писатель)

Физически: `docs/subagent-workflow/facts/<task-id>.jsonl` — на задачу один файл, пишет только владелец
задачи (агент-исполнитель свою задачу, приёмщик — вердикты, движок — gate-факты). Генезис-запись
`{kind: genesis, task, contract_hash, at, writer}` открывает цепь; `prev` — хеш предыдущей строки.
Крос-задачные view собираются из файлов при чтении; сжатие (compaction) — старые строки в архив с
хешем, без переписывания. Ограничение длины пути Windows — файлы внутри воркспейса, имя ≤ 80 симв.

| Отношение | Поля | Примечания после ревью |
| --- | --- | --- |
| `task` | id, contract_hash, base_commit, risk, declared_paths, writer, at | |
| `contract` | task, hash, criteria, allowed_paths, no_touch, writer, at | |
| `run` | id, task, commit, ruleset_hash, command, start, end, writer | **новое**: все доказательства ссылаются на один run |
| `diff` | task, run, base, commit, paths, diff_hash, writer, at | |
| `evidence` | task, run, kind, gate, artifact_hash, exit, seal_hash, writer, at | `gate` для C5; `seal_hash` из `ruleset.seal` |
| `judgment` | task, run, artifact_hash, by, role, model, verdict, rationale_hash, independent, writer, at | `role` из графа; `independent` вычисляется движком, не заявляется моделью |
| `accept` | task, run, contract_hash, diff_hash, ruleset_hash, evidence_manifest_hash, by, at | манифест = полный закрытый список доказательств с хешами |
| `release` | version, tag, asset, size, smoke_hash, receipt_hash, at | |
| `ruleset` | version, anchors_hash, presets_hash, seal, policy_json, signature, at | `signature` — вложенная форма 0.3; `seal` — хеш запечатанного набора тестов |
| `action` | task, run, cmd, paths, at, writer | **новое**: фактические действия из журнала исполнителя — источник для C8 |

## 3. Ограничения

```
C1  accept(t) ⇐ ∃ run(t, commit=base, ruleset=r) ∧ contract(t, hash=task.contract_hash)
C2  accept(t) ⇐ evidence(t, run, kind=sealed_run, seal_hash=ruleset.seal, exit=0) — один раз на run
C3  ∀p∈diff.paths: normalize(p) ∉ forbidden — normalize: нижний регистр + прямые слеши + раскрытие
C4  accept(t) ⇐ judgment(t, run, artifact_hash=diff.diff_hash, verdict=accepted, independent=1,
    role∈reviewer, model_family≠executor_family)
C5  accept(t) ⇐ ∀g∈policy(ruleset, task.risk): evidence(t, run, kind=gate_run, gate=g, exit=0)
C6  release(v) ⇐ asset(v) ∧ smoke_hash(v) ∧ receipt_hash(v) ∧ tag=v
C7  цепь: genesis у корня, prev у каждой строки, единственный писатель файла;
    старые записи без prev получают genesis конвертером (§6)
C8  findings(t) ⊇ {(cmd,path) ∈ action(t) ∖ planned(t)} — planned из contract.declared_paths
C9  ruleset(v+1) ⇐ signature.covers='hash+by+at' человеческого ключа над hash(ruleset) — как 2.6.80
C10 accept(t) атомарен: свидетельство и метаданные одним коммитом;
    плюс: единственность accept и verdict на (task, run); конфликтные факты → отказ;
    добавление факта не может улучшить вердикт (монотонность — §5)
```

## 5. Свойство «проверка краснеет» (позитив + негатив)

- негатив: убрать обязательный факт → отказ;
- позитив (из ревью): добавить дубль evidence, старый run, лишний gate_run, факт от другого task,
  подменить commit/ruleset/artifact_hash, «свежий» judgment на старый дифф → отказ или нейтралитет;
- монотонность: добавление нерелевантного факта не меняет вердикт к лучшему; конфликт/дубль — краснеет;
- бюджет: ~15 ограничений × ~5 мутаций ≈ 75 кейсов, фиксированный запуск в selftest;
- oracle: ожидаемый вердикт кейса пишется вручную до запуска (защита от повторения ошибки ограничения).

## 6. Миграция

| Этап | Что | Критерий перехода |
| --- | --- | --- |
| P0 | схема + исполнитель + конвертер генезисов; читает, ничего не меняет | вердикты совпадают с текущими на закреплённом корпусе (5 задач, зафиксированы до старта) |
| P1 | C1–C5 тенью | 5 задач: ноль необъяснённых расхождений; каждое расхождение разбирает независимый приёмщик с записью |
| P2 | переключение `task-accept`; 59 модулей за шимом | предельный срок шима: 2 задачи; есть процедура отката к проверкам |
| P3 | удаление дублей | **каждый удалённый selftest-шаг имеет замещающее ограничение с негативным кейсом**; покрытие не падает, а переезжает |

## 7. Риски (дополнено)

1. **Windows:** NTFS без учёта регистра — нормализация в C3; запрет пайпов в подпроцессах
   (spawnSyncPipeFree) — исполнитель не использует pipe-захват; путь ≤ 260 — факты в коротких именах.
2. **Производительность:** файл на задачу — чтение O(задача); крос-задачные view — компактный индекс,
   пересобираемый после записи; retention: архив старше N задач с хешем.
3. **Обратная совместимость:** конвертер пишет генезис и новые факты, старые записи не меняет.
4. **Запрет третьего уровня в потоке:** остаётся; аудит по выборке вместо него.
5. **Человеческая подпись (C9):** обязательна, форма — вложенная signature из 2.6.80.
