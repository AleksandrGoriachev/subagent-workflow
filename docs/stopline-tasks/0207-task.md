# 0207 — Регрессионный гейт в приёмке

## Зачем

`task-regress.mjs` написан, но в `task-accept` — 0 упоминаний; вне e2e регрессии не перезапускаются.
Гниение приёмки не ловится: старые проверки гоняются, только если новая задача сама о них вспомнит.

## Что сделать

1. Подключить `task-regress` в `task-accept` после `verify`, до `accepted`.
2. Провал регресса — отказ приёмки с перечнем упавших задач и критериев.
3. Ночной запуск регресса (расписание или `tools/test.mjs`), не только e2e.
4. **До включения** — baseline-прогон и allowlist известных провалов (список из письма 46).

## Критерии

Внешний чек: `spec/checks/stopline/t1-regress-gate.mjs` (3 проверки). Плюс свой `checks/0207-regress-gate.mjs`,
который доказывает: сломанная проверка принятой задачи валит приёмку новой.

## Почему C5 (после ревью B1)

`task-regress.mjs` входит в `allowedPaths`, значит он меняется — и обязан быть покрыт критерием.
Без этого `policy.coverage=fail` даёт `uncovered` и verify падает, даже когда сам гейт работает.

## Не входит

Новые проверки, изменение существующих чеков, UI.
