# 0210 — доставка писем обмена

## Зачем

11.11 watcher перестал обходить `coordination/threads/exchange` с 16:10: письма 51/52 не были
доставлены ни нам, ни вам; журнал `exchange-seen.json` фиксирует сканирование, а не вручение.
Координация держалась на заказчике, который пересказывал письма вручную.

## Что сделать

1. Скан по независимому таймеру (не по активности сессии) и **heartbeat** на каждом тике:
   `~/.dsh/project-graph/runs/exchange-watch.json` → `{ lastTickAt: ISO, scanned: N }`, не реже раза в минуту.
2. Журнал с состояниями: `scanned` (watermark каталога) и `delivered` (письмо показано/доставлено),
   плюс `pending` и `error`. Молчание должно отличаться от «писем нет».
3. Скан и доставка при старте сессии — независимо от того, была ли активность.
4. Тест: письмо, положенное при занятой сессии, доставляется после следующего тика (не теряется).

## Критерии (внешний чек `t4-exchange-delivery.mjs`)

- heartbeat не старше 5 минут;
- журнал различает scanned/delivered/pending/error;
- скан и доставка при старте сессии;
- есть тест на доставку при занятой сессии.

Baseline на HEAD: `T4: FAILED (2)` — нет heartbeat, нет состояний.

## Приоритет

Раньше T1: пока координация не восстановлена, остальные приёмки держатся на пересказе заказчика.

## Не входит

UI-индикация писем; изменение формата `dsh-exchange/1`.
