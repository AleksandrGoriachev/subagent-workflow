# Процедура пилота проектных якорей

Дата: 2026-11-10. Основание: решения заказчика по манифесту 0.3 и итогам обсуждения со structure.

## 1. Что проверяем

Три вопроса, которые нельзя закрыть схемой, только живым прогоном:

1. **Кто и как формулирует** якоря проекта — владелец с координатором проекта в диалоге;
2. **Как запись попадает в файл** — редактор structure (0192) пишет `docs/anchors.json`, подпись владельца — `docs/anchors.approval.json`;
3. **Как применяют узлы** — `consumes` в `graph.json`, гейт запуска, вердикты ревьювера, артефакты `proof`.

## 2. Порядок

1. Воркспейс выбирает заказчик; вход в него — только по W5 (разрешение, запись в `coordination/permits/`).
2. Владелец с координатором проекта формулируют 3–5 якорей. Каждый: `claim`, `check`, `proof` (команда + артефакт), `status`.
3. Редактор (0192) записывает файл; владелец подписывает человеческим ключом.
4. Узлы объявляют `consumes` со стадией `pre-work`/`pre-accept`.
5. Прогон задачи: гейт запуска требует `audit.json` по всем `consumes`; ревьювер даёт вердикты по `pre-accept`; `proof` прикладывается.
6. Приёмка пилота (наша сторона): `anchor-freshness --project <воркспейс>` — зелёный; журнал гейтов без обходов; вердикты привязаны к диффу.

## 3. Критерии успеха

- `anchor-freshness --project` — OK, якорей 3–5, подпись human-user;
- каждая задача прошла гейт с `audit.json`, где нет `notJudged` без причины;
- негативный кейс: задача, нарушающая якорь, **не принимается** (проверяется намеренно);
- правка якоря после подписи переводит набор в «изменено после подписи» — работа не блокируется, но видно.

## 4. Что считается провалом

- якорь нельзя проверить (`proof` пустой или командой нельзя воспользоваться);
- узел не вызван, а вердикт есть;
- вердикт не привязан к диффу (проверяли не то, что изменилось);
- подпись агентская или подделана — стоп и разбор.

## 5. После пилота

1. Расширяем на остальные воркспейсы по одному, а не сразу.
2. Включаем `guard.enabled` (WC-76) — гейт коммитов требует контракта задачи; на пилоте это уже проверено на живых задачах.
3. Проектные якоря попадают в панель (наша сторона показывает read-only, structure — редактирует).
