## Правила стоп-линии (обязательны для всех трёх)

1. Критерии фиксируются **до** начала кода и не меняются исполнителем; правка критериев — только через exchange.
2. Внешние чеки живут в нашем репозитории: `spec/checks/stopline/t1..t3`. Исполнитель может гонять их локально, но доказательством считается прогон на нашей стороне.
3. Провал любого чека блокирует приёмку. Зелёные логи исполнителя доказательством не являются.
4. Новые фичи не входят. Только перечисленные ниже изменения; всё остальное — в очередь.
5. Приёмка идёт на чистом клоне: чеки не должны требовать файлов, созданных исполнителем после фиксации.

## T3 (v2). Якоря — глобальные, у узла — гейты; `consumes` удаляется + чистый реестр

**Модель заказчика (11.11):** якоря пишутся для всей структуры; к конкретному узлу применяются **гейты**.
Отсюда противоречие A8 ↔ 0206 снимается не выбором одной из сторон, а удалением предмета спора:
если `anchors.consumes` у узла нет, то и «пустой consumes → отказ» против «все auto» — не два ответа.

**Схема:**

```json
{ "id": "reviewer-1", "role": "ревьюер", "gates": ["review-receipt", "anchor-binding"] }
{ "id": "release-1",  "role": "выпускающий", "gates": ["preset", "release-receipt", "accept-line"] }
```

**Что сделать:**
- из схемы узла убрать `anchors.consumes`; legacy-графы читать с предупреждением «consumes устарел», не ломая;
- узел объявляет `gates` — список гейтов, проверяемых до/после его действия; реестр гейтов — в коде;
- **пустой список гейтов у проверяющей (reviewer/аудитор/judge) и релизной роли — отказ**, не «закрыт»;
- A8 переписать: «якоря действуют на всю структуру; узел без гейтов считается незакрытым; гейт ревьюера — квитанция ревью»;
- `role-policy.js` свести к выбору модели/промпта: `all-auto` и `defaultConsumes` удаляются;
- проверки `0186`/`0192`, гонявшие `consumes`, заменить на проверку гейтов (внешним чеком, не исполнителем);
- реестр: фантомные `open` → `cancelled` со ссылкой «→ NNNN».

**Критерии (внешний чек `t3-policy-truth.mjs`, v2):**
- A8 больше не требует `consumes` у узла;
- узел объявляет `gates`, а не `consumes`;
- пустые `gates` у проверяющей/релизной роли — отказ;
- `role-policy` не раздаёт `all-auto`;
- фантомных `open` — 0.

**Подпись A8:** утверждает владелец (заказчик), не агент. Текст на утверждение — `docs/A8-NEW-WORDING.md`.

**Не входит:** переписывание всех проверок якорей глубже 0186/0192; UI-редактор гейтов.

**Критерии (внешний чек `t3-policy-truth.mjs`, v3):**

подписать тем же инструментом; это проверяется внешним чеком T3 и ручным прогоном панели.

## C3 переформулирован (11.11, решение заказчика): не «ночью», а «автоматически»

«Ночной запуск» был моей формулировкой, а не требованием; время взялось из расписания `tester-1`.
Требование по сути: регресс запускается **вне приёмки, автоматически, без памяти человека**; время суток — любое.

Новая формулировка C3:

> «Есть автозапуск регресса вне приёмки: планировщик вызывает его периодически (время любое).»

Доказательство — evidence-файл `spec/checks/stopline/regress-schedule.json` рядом с чеком:
`{ schedule, lastRunAt, exit, by }`; чек требует `lastRunAt` не старше 26 часов. Файл пишет сам
запуск, а не человек; «строка в промпте» доказательством не считается.

Автозапуск создан 11.11 в 17:14 MSK (`schedule-46c53eb5`), первая сработка — через ~3 минуты,
далее ежедневно; цель — этот же воркспейс, только чтение их проекта и запуск их `task-regress`.
