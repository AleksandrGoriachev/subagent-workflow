## Цель

Убрать ручную правку карты движков как единственный способ связать воркспейс с движком: связь
объявляется конфигом плагина (в момент включения) или выбирается кнопкой в панели по подтверждению,
а резолвер честно называет источник. Карточка «движок не подключён» перестаёт быть сообщением об
ошибке и становится выбором из двух равных действий.

## Зачем

Сейчас внешний движок подключается только правкой JSON-карты руками. Это работает, но требует
знания формата, не видно из панели и не имеет декларативной формы: при переносе профиля на другую
машину связь теряется молча. Заказчик выбрал A + кнопку: декларация в конфиге профиля, а если её
нет — выбор в панели, без движка «по умолчанию».

## Что не входит

1. Движок «по умолчанию» (engines.default) не вводится: каждая связь явная.
2. Правка YAML профиля из панели запрещена: кнопка пишет только карту, YAML читается при старте DSH.
3. Метаданные реестра DSH не используются — это решение §4 хендовера, обосновано в D1.
4. Запрет записи в воркспейс с внешним движком (409 engine-external) не меняется.
5. Выпуск версии, теги и релиз — после приёмки, руками архитектора; задание версию не двигает.

## Инварианты

1. **Резолвер.** Порядок источников: local (движок внутри воркспейса) → config (декларативная связь из
   конфига плагина) → карта движков → absent. Ответ содержит
   {installed, mode: local|mapped|absent, root, version, source: workspace|config|mapping|none}.
   version читается из маркера VERSION развёрнутой копии; относительные пути и записи без движка
   связью не считаются.
2. **Конфиг сильнее карты.** Связь, объявленная декларативно, кнопкой не подменяется: POST
   /api/engine-link для такого воркспейса отвечает 409 с кодом engine-config, карта не меняется.
3. **Кнопка.** POST /api/engine-link принимает только application/json, только свой Origin, только с
   confirm: true. Без подтверждения — 400 и никакой записи. Запись карты атомарная: временный файл в
   том же каталоге и переименование; после успеха в каталоге карты нет посторонних файлов. Цель
   обязана быть разрешённым корнем и содержать движок; иначе 400 (not-an-engine для каталога без
   движка).
4. **Кандидаты.** GET /api/engine/candidates?root=… отдаёт зарегистрированные воркспейсы, где есть
   движок, с версией и признаком current; воркспейсы без движка и несуществующие пути в список не
   попадают.
5. **Карточка.** При absent: заголовок «движок не подключён», два равноправных действия «Развернуть
   здесь» и «Подключить существующий» (список кандидатов с версиями), ни слова «ошибка», ни
   тревожного цвета. При mapped: путь, версия и источник словами «задано конфигом профиля» или
   «выбрано в панели»; при local — «здесь».
6. **Развернуть здесь на не-git воркспейсе** выполняет шаг git init, затем разворачивает движок:
   иначе ворота задания не работают, а пользователь видит только отказ git.
7. **init.** init --external <path> пишет карту и выходит, ничего не разворачивая; если в <path> нет
   движка — ненулевой код и карта не меняется. init --git-init инициализирует репозиторий, если его
   нет, и продолжает обычное развёртывание.
8. Чужие зоны не трогаются: проверка задания и файлы задания защищены замком; не коммитить, не
   пушить, не ставить теги.

## Среда

- Node.js 20+, Windows, git в PATH; сеть не нужна.
- Проверки пишут только во временные каталоги и не трогают домашнюю карту пользователя: путь карты
  задаётся env WF_ENGINE_ROOTS.
- В песочнице DSH дочерние процессы с pipe-выводом запрещены: проверка захватывает вывод через файлы.
  Если твой прогон упирается в EPERM на spawn, это признак среды, а не кода — скажи в отчёте.

## Что сделать

1. **plugin/lib/engine-root.js** — resolveEngine(root, { config, file, env }) по инварианту 1: чтение
   декларативной связи из config.engines.roots, версия из VERSION, mode и source в ответе; engineView
   проецирует mode, version, source для /api/status. Старое поведение (workspace/mapping/none)
   сохраняется: нынешние тесты и 409 engine-external не ломаются.
2. **plugin/lib/api.js** — createWorkflowRuntime принимает engines.roots и передаёт его резолверу во
   всех местах чтения; в /api/status поле engine — по инварианту 1; новый GET /api/engine/candidates;
   новый POST /api/engine-link в списке изменяющих маршрутов с теми же проверками типа и Origin, что
   у /api/guard, и с 409 engine-config по инварианту 2.
3. **plugin/lib/deploy.js** — развёртывание из панели умеет шаг git init, когда корень не является
   git-репозиторием (тело /api/deploy: initGit: true); без флага поведение прежнее.
4. **plugin/lib/client.js** — карточка движка по инварианту 5: тексты «движок не подключён»,
   «Развернуть здесь», «Подключить существующий», источники «задано конфигом профиля» / «выбрано в
   панели»; выбор кандидата вызывает /api/engine-link с confirm: true и перечитывает состояние.
5. **plugin/test/** — тесты резолвера с config, маршрутов engine-link и candidates, карточки. Два
   теста обязаны называться ровно «0.9.3 absent: два действия, без ошибки» и
   «0.9.3 mapped: путь, версия, источник»: их ищет проверка задания.
6. **spec/scripts/init.mjs** — флаги --external и --git-init по инварианту 7; запись карты тем же
   форматом, что читает плагин, и атомарно.
7. **spec/SPEC.md** — короткий раздел: порядок источников связи, флаги init, что карту из панели
   пишет только /api/engine-link и только по подтверждению.
