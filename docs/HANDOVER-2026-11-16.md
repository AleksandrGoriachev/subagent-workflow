## 4. Правила, которые нельзя нарушать

- **Линейность**: задача → контракт → red → код → verify → приёмка → metadata-коммит; следующая задача только после закрытия текущей. Одна задача — один коммит.
- **Никакого снижения контроля**: без `--allow-missing-red`; allowlist только для реально предсуществующих провалов с owner/reviewBy; «код в main» без приёмки запрещён.
- **Код пишет worker**, контракт/критерии — координатор. Приёмка — judge, подписью ключа.
- **Контракт нельзя выпустить без preflight**: сторож требует `docs/tasks/<id>/preflight.json` со свежим `contractSha`; метка `[workflow-bypass]` на контракт не действует.
- **Замок после red не переписывается**: любое изменение `task.md`/`criteria.json` = новый ID и новый red. **Никогда не коммитить артефакты red/verify до приёмки** (0274 на этом потеряла час: коммит артефактов сдвинул HEAD и отвязал кандидата).
- **Ожидание приёмки** — короткими проверками (`acceptance.json` + `list_agents`), не одним длинным сном; лучший способ — ждать фоновый job `job.mjs wait <id>`.
- **Приёмку запускать с `--fast`** (кроме случаев, когда дифф задевает тяжёлые проверки).
