# Ящик обмена: независимая проверка и память прочтения

Инструмент: [tools/exchange-inbox.mjs](../tools/exchange-inbox.mjs). Тесты:
[plugin/test/exchange-inbox.test.mjs](../plugin/test/exchange-inbox.test.mjs) (c1–c6).

## Зачем

Плагин structure доставляет письма и ведёт журнал `~/.dsh/project-graph/runs/exchange-seen.json`.
Журнал фиксирует **сканирование**, а не вручение, и может отставать (дефект 11.11:
[EXCHANGE-DELIVERY-BUG.md](EXCHANGE-DELIVERY-BUG.md)). Поэтому «мне не приходило» — не доказательство.
Инструмент читает каталог писем сам и показывает то, что не отмечено.

## Запуск

```
node tools/exchange-inbox.mjs [--dir <каталог>] [--memory-dir <каталог>]
                              [--seen <журнал плагина>] [--mark [<письмо>...]]
```

| ключ | смысл |
| --- | --- |
| `--dir` | каталог обмена; по умолчанию общий `coordination/threads/exchange` |
| `--memory-dir` | каталог памяти прочтения; по умолчанию `<пакет>/.tmp/exchange-seen` |
| `--seen` | журнал плагина как **дополнительный** источник отметок (не доказательство) |
| `--mark <письмо...>` | точечная отметка: одно или несколько имён (через пробел или запятую) |
| `--mark` без имён | пакетная отметка всего показанного + поднятие watermark |
| `--help` | краткая справка |

Коды выхода: `0` — непрочитанных нет; `1` — есть непрочитанные (или не найдены названные
письма); `2` — ошибка аргументов.

## Память прочтения — по корню каталога

Файл памяти: `<memory-dir>/<sha256(нормализованный корень)[:16]>.json`.
По умолчанию `<memory-dir>` — это `<пакет>/.tmp/exchange-seen`: `.tmp` исключён из архива
(`tools/pack.mjs`) и из git (`.gitignore`), поэтому память не уезжает в релиз и не требует
записи в домашний каталог, которую песочница DSH (workspace-write) запрещает.
Переопределяется ключом `--memory-dir` или переменной `WF_EXCHANGE_MEMORY_DIR`.
Два разных каталога обмена (например, у двух сторон) больше не делят одну отметку: у каждого
свой файл, даже если письма называются одинаково.

```json
{
  "version": 2,
  "root": "C:\\...\\coordination\\threads\\exchange",
  "watermark": 1763...,
  "letters": { "2026-11-18T00-30+03-00--structure--210.md": 1763... },
  "updatedAt": "2026-11-18T..."
}
```

- `letters` — точечные отметки: письмо с таким именем считается прочитанным всегда;
- `watermark` — граница истории: письмо старше или равное ей считается просмотренным
  (защита от лавины легаси-писем до начала учёта). При первой загрузке watermark берётся
  из журнала плагина по этому каталогу; пакетная `--mark` поднимает его до самого нового письма.

Письмо, отмеченное в журнале плагина по имени, тоже считается прочитанным — так старые
вручения не всплывают заново. Но журнал плагина **читается, а не считается истиной**: письма,
которых в нём нет, показываются независимо от него.

## Почему точечная отметка, а не только пакетная

Пакетная отметка «всё прочитано» скрывает то, что ещё не разобрано. Точечная позволяет
отметить ровно разобранные письма (например, `structure--210`) и оставить в списке остальные.
Повторная отметка того же письма безопасна: оно уходит в `уже отмечено` и файл не меняется.
