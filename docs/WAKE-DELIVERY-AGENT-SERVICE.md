# Wake-доставка: сбой «служба агентов не приняла сообщение» (фидбэк второго харнеса)

Дата: 2026-11-11, 23:00. Источник: фронтенд-харнесс (ветка `architecture`), письмо `--48`.

## Симптом

```
22:19:49 → error: живая сессия найдена, но служба агентов не приняла сообщение:
          Cannot read properties of undefined (reading 'length')
22:19:53 → skip:cooldown (ретрай через 120 с)
```

Письма от бэка к фронту доставляются (`delivered`), а от фронта к бэку падают на wake. То есть
проблема не в ящике и не в адресации, а в вызове службы агентов при вручении в **живую** сессию.

## Где это в коде

`lib/exchange-watch.js:3046–3057` (и тот же путь в `lib/digest.js:421`):

```js
const call = typeof handle.sendMessage === 'function'
  ? handle.sendMessage({ text })
  : (typeof handle.send === 'function' ? handle.send({ text }) : null);
```

Ошибка `reading 'length'` возникает **внутри** службы агентов, а не в watcher: она получает объект
`{ text }` и падает на попытке прочитать длину несуществующего поля (вероятно `parts`/`content`).

## Почему у нас это не воспроизводится

В нашем харнессе wake сработал: `workflow--145` → `branch: delivered, cause: delivered:wake`.
Значит у фронта служба агентов другой сборки/адаптера и ожидает иной формы сообщения.

## Что предлагаю (defensive delivery)

1. Пробовать несколько форм по очереди: `{ text }`, затем `{ text, parts: [{ type: 'text', text }] }`,
   затем `{ text, content: [{ type: 'text', text }] }`;
2. Ошибку каждой попытки писать в `exchange-decisions.jsonl` с формой, а не только сообщением;
3. Не считать падение wake потерей письма: статус остаётся `pending`, cooldown-ретрай сохраняется
   (сейчас так и есть — поэтому письмо не потерялось, его прочитал цикл бэка).

## Побочное замечание

`tools/check-exchange.mjs` у фронта отсутствует и не должен быть: это инструмент координатора.
Их корректный путь — читать ящик напрямую или использовать свой штатный цикл.
