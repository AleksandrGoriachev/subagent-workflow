# Адаптеры харнессов

Ворота не зависят от харнесса. Им нужны ровно две вещи:

1. **Идентификатор сессии агента** в окружении процесса — стабильный на время работы
   агента и разный у постановщика, исполнителя и приёмщика.
2. **Возможность запустить приёмку в другой сессии** — любым механизмом харнесса
   (субагент, отдельный процесс, отдельный чат), без отчёта исполнителя.

Если харнесс не даёт идентификатор, ворота не выдумывают его: актор помечается
`declared`, и это допустимо только для `low`. Medium/high без аттестации не
принимаются — так и задумано.

## Как подключить новый харнесс

1. Узнайте, что видит процесс:

~~~bash
node docs/subagent-workflow/scripts/actor.mjs --json
~~~

2. Найдите переменную с идентификатором сессии/агента (или задайте свою в обёртке).
3. Пропишите её в `docs/subagent-workflow/workflow.config.json`:

~~~json
{ "actor": { "primaryEnv": "MY_HARNESS_SESSION_ID", "modelEnv": "MY_HARNESS_MODEL" } }
~~~

4. Проверьте:

~~~bash
node docs/subagent-workflow/scripts/actor.mjs --risk medium   # exit 0 — medium возможен
node docs/subagent-workflow/scripts/doctor.mjs --repo .
~~~

## Матрица

| Харнесс | Переменная | Что даёт | Приёмка |
| --- | --- | --- | --- |
| DSH | `DSH_SESSION_ID` | своя сессия у каждого агента, доходит до child-процессов | субагент в отдельной сессии |
| Иной агентный раннер | своя, через `primaryEnv` | зависит от раннера | отдельная сессия/чат |
| CI | id джобы | та же машина, не независимый агент | только проверка записей, не создание |
| Человек | — | ключ `human-*` | high-risk подписывает человек |

Подробности: `dsh.md`, `generic.md`, `ci.md`.
